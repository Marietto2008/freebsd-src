# T0.3 — Script di collaudo (gate D3 per i nomi dei flag)

## Cosa c'e' (tutti con set -eu, log in $NESTED_ROOT/logs, --prova)
- `session-setup.sh`: setup UNA TANTUM del BE di collaudo (§8): crash dump
  (dumpdev=AUTO, dumpdir=$NESTED_ROOT/crash, dumpon_flags=-Z per ZSTDIO),
  **debug.debugger_on_panic=0** + panic_reboot_wait_time=5 in sysctl.conf,
  gdb per crashinfo, promemoria della prova di dump (sysctl debug.kdb.panic=1).
- `load.sh`: scarica/carica `vmm-restore.ko` da $STAGE nel BE di collaudo,
  imposta i tunable (debug_trace=0, qemu_mode_mask=15, vlapic_debug_lowvec=0)
  PRIMA del load, verifica (§7.5). Controlli: root, nessuna VM in /dev/vmm.
  Mai da /boot, mai in loader.conf.
- `kut-run.sh [--nested] <lista>`: runner kvm-unit-tests al posto di
  run_tests.sh/x86/run (§7.4). `--nested` aggiunge `,nested=on` all'accel.
  Riga QEMU con pc-testdev/isa-debug-exit; codice d'uscita (c<<1)|1; seriale
  e stderr separati; riassunto per fase.
- `run-l1.sh --img ... [--front bhyve|accel]`: avvia un L1 con la capability
  nested accesa (bhyve -S -o x86.nested_virt=true, oppure QEMU
  -accel bhyve,nested=on), per F3/F4.
- `collect.sh`: pacchetto di log per Claude Code (§7.6): MANIFEST, uname,
  kldstat, sysctl, seriali/stderr dei test, crash dump, report .md + .tar.xz;
  `--dtrace` aggrega le probe vmm:vmx:nested:*.
- `kut-f1.list` / `kut-f2a.list` / `kut-f2b.list` / `kut-f2c.list`: le liste
  per fase (nome|file|args|qemu_params|smp|mem|timeout).

## Collaudo (Claude Code)
`sh -n` su tutti e 5 gli script: OK. `--prova` mostra la sequenza attesa senza
eseguire nulla (kldload/pkg/bhyve solo echo). Claude Code non li lancia MAI
senza --prova.

## Nota su $NESTED_ROOT
Default `/nested` (dataset ZFS fuori dai BE, §7.2). Si puo' ridefinire in
nested.env. Il set esatto di F2c va allineato a unittests.cfg (vedi kut-f2c.list).
