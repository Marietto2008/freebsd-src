# T1.7 — VMXON, VMXOFF, VMCLEAR, VMPTRLD, VMPTRST

## Cosa c'e'
- `vmx.c`: le istruzioni VMX (EXIT_REASON_VM*) con la capability nested attiva
  vanno a `VM_EXITCODE_NESTED` (slow path) invece di VM_EXITCODE_VMINSN/#UD.
  Esposti (tolto `static`) 4 helper usati dal nested: `vmx_get_guest_reg`,
  `vmx_getdesc`, `vmx_paging_info`, `vmx_cpu_mode` (prototipi in vmx_nested.h).
- `vmx_nested.c`:
  * `nested_operand_gpa()`: decodifica l'operando di memoria VMX dal campo
    VM-exit instruction-information (addrsize 9:7, seg 17:15, index 21:18
    invalido a bit 22, base 26:23 invalido a bit 27 — formato SDM/KVM, lo
    stesso usato da inout_str_*) + displacement = exit qualification, poi
    `vie_calculate_gla` + `vm_gla2gpa` -> GPA dell'L1; inietta #GP/#PF se serve.
  * `nested_read_operand_u64()`: legge gli 8 byte via vm_gpa_hold/release.
  * `nested_vmx_result()` / `nested_vmfail_invalid()`: esito nel RFLAGS dell'L1
    (VMsucceed / VMfailValid(errnum) con VMCS_INSTRUCTION_ERROR / VMfailInvalid).
  * `nested_advance_rip()`: avanza GUEST_RIP di EXIT_INSTRUCTION_LENGTH.
  * handler: VMXON (set vmxon+vmxon_ptr), VMXOFF (azzera stato),
    VMCLEAR (evince dalla cache, azzera current se coincide),
    VMPTRLD (valida allineamento/≠vmxon_ptr, trova/crea voce di cache, set
    current_vmcs12), VMPTRST (scrive current_vmcs12 all'operando).
  * `vmx_nested_exit()` ora dispatcha sull'exit reason; VMLAUNCH/VMRESUME
    (T2.4), VMREAD/VMWRITE (T1.8) e VMCALL -> #UD per ora.

## Limiti v1 (deviazioni.md)
Controlli SDM completi di VMXON (CR0/CR4 fixed, CPL, revisione/allineamento
della VMXON region) e verifica della revisione del VMCS12 in VMPTRLD: rimandati.
La scrittura del launch-state nel VMCS12 in memoria (VMCLEAR): T1.8/T2. La
cache usa un'evizione banale (slot 0) quando piena.
