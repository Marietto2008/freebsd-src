# T2.9 — I/O, MSR, MWAIT/MONITOR di L2

## Cosa c'e'
In `nested_l2_exit`, decisione rifletti-vs-L0 secondo gli intercetti di VMCS12
(§6.4), con lettura delle bitmap di VMCS12 dalla memoria dell'L1
(`nested_bitmap_bit` via vm_gpa_hold):
- **INOUT**: VMCS12 con unconditional I/O -> riflette; con I/O bitmaps -> legge
  il bit della porta (A: <0x8000, B: >=0x8000) -> riflette se impostato;
  altrimenti L0 gestisce l'I/O con i registri di L2 (return false).
- **RDMSR/WRMSR**: senza MSR bitmaps in VMCS12 -> riflette (tutte intercettate);
  con MSR bitmaps -> legge il bit giusto (read/write, low 0-1FFF / high
  C0000000-C0001FFF) -> riflette se impostato; altrimenti L0.
- **MWAIT/MONITOR**: VMCS12 intercetta -> riflette; altrimenti #UD in L2.
- Unificato: nel dispatch, `break` = rifletti all'L1 (post-switch); `return
  false` = gestito dall'L0 e si rientra in L2.

## Rimandato
Il caso EPT01-miss (RAM non residente -> vm_fault; MMIO -> emulazione in
contesto L2 con l'invariante L1-GPA di §6.7.5, che richiede di tradurre in
_vm_gla2gpa attraverso EPT12) resta RIFLESSO all'L1 (da T2.7). E' il pezzo che
tocca vmm_instruction_emul.c (anche in libvmmapi): da fare quando serve l'MMIO
emulato in L2 (dispositivi emulati visti dalla root partition di Hyper-V).
CR8 / MOV CR0-CR4 di L2 restano nel ramo default (riflessi); l'affinamento
CR8->TPR del vlapic dell'L1 e le regole mask di §6.4 sono un seguito.

## Collaudo
Compile: modulo vmm -Werror EXIT 0. Hardware: I/O_bitmap, MSR_switch.
