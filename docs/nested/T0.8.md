# T0.8 — Foglia 0x40000001 con firma KVM coerente (D6 = A)

## Cosa e' cambiato
- `sys/x86/include/bhyve.h`: `CPUID_BHYVE_FEAT_EXT_DEST_ID` da `(1UL << 0)` a
  `(1UL << 15)`. La firma hypervisor resta `"KVMKVMKVM"` (x86.c:56); la foglia
  0x40000001 EAX (x86.c:627, che usa il macro) ora espone la feature MSI
  Extended Dest ID al bit 15, che e' `KVM_FEATURE_MSI_EXT_DEST_ID` nella
  tabella KVM. Al bit 0 un L1 KVM-aware leggeva `KVM_FEATURE_CLOCKSOURCE`
  (kvmclock legacy su MSR 0x11/0x12), non emulato -> errori.

Nessun altro codice usa il macro (solo x86.c:627), quindi il cambio tocca solo
cio' che viene annunciato al guest. Vale per TUTTE le VM, non solo il nested.

## Collaudo (Marietto, durante R / in F3)
In un guest Linux: `cpuid -1 -l 0x40000001` deve mostrare EAX con bit 15 (non
bit 0), e `dmesg` del guest non deve mostrare accessi agli MSR 0x11/0x12.
Compile-check: modulo vmm ricostruito -Werror.
