# T1.2 — Capability VM_CAP_NESTED_VIRT (D3 = A + D3.b(i))

## Cosa e' cambiato
- `sys/amd64/include/vmm.h`: `VM_CAP_NESTED_VIRT` nell'enum, subito prima di
  `VM_CAP_MAX`.
- `lib/libvmmapi/amd64/vmmapi_machdep.c`: `vm_capstrmap[VM_CAP_NESTED_VIRT] =
  "nested_virt"`.
- `sys/amd64/vmm/intel/vmx.h`: campo `int has_run` in `struct vmx_vcpu`.
- `sys/amd64/vmm/intel/vmx.c`:
  * `vmx_getcap`: `VM_CAP_NESTED_VIRT` -> supportata (ret 0); il valore viene
    da `cap.set` come le altre;
  * `vmx_setcap`: capability virtuale (nessun controllo VMCS), registra solo
    `cap.set`; **0->1 ammesso solo se `!has_run`** (prima del primo vmx_run o
    dopo un reset), altrimenti `EBUSY`. L'allocazione dello stato nested e' T1.3;
  * `vmx_run`: `vcpu->has_run = 1` all'ingresso.
- `sys/amd64/vmm/amd/svm.c`: `svm_setcap` restituisce `ENOENT` per
  `VM_CAP_NESTED_VIRT` (su AMD non esiste).
- `sys/dev/vmm/vmm_dev.c`: nel caso ioctl `VM_SET_CAPABILITY`, accendere
  `VM_CAP_NESTED_VIRT` richiede `priv_check(td, PRIV_DRIVER)` (D3.b(i)),
  sotto `#ifdef __amd64__`.
- `usr.sbin/bhyve/amd64/bhyverun_machdep.c`: `bhyve_init_vcpu` accende la
  capability se `-o x86.nested_virt=true`; errore del kernel = fatale.

## Manpage
`bhyve.8` NON documenta alcun config `x86.*` (0 occorrenze: vmexit_on_hlt,
x2apic ecc. non ci sono). Per coerenza col resto non ho aggiunto una sezione
solo per `x86.nested_virt`. Da rivedere se si decide di documentare tutti i
config x86 insieme.

## Collaudo (Marietto; Claude Code: solo compile)
Compile-check: modulo vmm (-Werror, VMMSNOOP) + libvmmapi + bhyve + bhyvectl.
Sull'hardware:
- `bhyvectl --vm=<vm> --getcap --capname=nested_virt` -> 0 di default,
  1 con `-o x86.nested_virt=true`;
- da utente non-root del gruppo `vmm`, accenderla deve dare EPERM (D3.b(i));
- regressione R: con la capability spenta, CPUID/MSR/exit identici a prima.

## Default 0
Nessun sysctl/tunable la accende globalmente. Con la capability a 0 il codice
nuovo (da T1.3) non e' raggiungibile.
