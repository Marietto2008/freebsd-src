# T1.8 — VMREAD/VMWRITE e VMCS shadowing

## Cosa c'e'
- `vmx.c`: esposto `vmx_set_guest_reg` (per la destinazione registro di VMREAD).
- `vmx_nested.h`: store software dei campi VMCS12 nella voce di cache
  (`struct vmcs12_field {enc,val}`, `fields[256]`, `nfields`) + proto setter.
- `vmx_nested.c`:
  * `nested_current_cache()`: la voce di cache del VMCS12 corrente.
  * `vmcs12_read_field()/vmcs12_write_field()`: store lineare per encoding.
  * `nested_vmread()/nested_vmwrite()`: decode operando (campo in reg2 bit
    31:28; valore/dest in reg1 bit 6:3 se registro, bit 10; altrimenti m64 via
    nested_operand_gpa), lettura/scrittura sullo store, esito nel RFLAGS.
    VMWRITE: F0 dice MISC bit 29 (VMWRITE-any) = SI, quindi nessun rifiuto dei
    campi read-only. Dispatch aggiunto in vmx_nested_exit.

## Scelta di progetto: software, niente shadowing hardware ANCORA
Senza VMCS shadowing abilitato in VMCS01, VMREAD/VMWRITE in VMX non-root
escono SEMPRE: le gestiamo in software sullo store. E' CORRETTO (e sicuro:
nessuna manipolazione del puntatore VMCS01 attivo, che corromperebbe lo stato
del guest in esecuzione). Lo shadowing hardware di §6.2 (bitmap S_R/S_W +
link pointer a VMCS02 in VMCS01) e' un'OTTIMIZZAZIONE che richiede la pagina
VMCS02 (T2.2) e si aggiunge dopo. Flag: deviazioni.md.
